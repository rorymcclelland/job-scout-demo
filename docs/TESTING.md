# Job Scout: testing

_Version 0.14.0 · 21 October 2026_

## Automated tests

`npm test` runs <!-- fact:code-tests -->151<!-- /fact --> tests with Node's built-in runner, on made-up emails shaped like the real ones (`test\fixtures\`). `npm run typecheck` runs the TypeScript compiler in strict mode with no output. Both pass at version 0.14.0. The tests read their own config (`test\fixtures\config\`, with Singapore as the second market) through `JOB_SCOUT_CONFIG_DIR`, set by `test\setup.ts`, so they do not depend on the owner's settings. `npm run test:tools` runs the <!-- fact:tool-tests -->164<!-- /fact --> tool tests: the evaluation (`tools\test_eval_scores.py`), the risk register (`tools\test_risk_register.py`), replies, matching, moves, the Inbox and Calendar documents and the weekly replies section (`tools\test_replies.py`), the output checker (`tools\test_validate.py`), the reviewer's claims check (`tools\test_claims.py`), the letter word count (`tools\test_build_pack.py`), the audit trail (`tools\test_ledger.py`), the public export and its scan (`tools\test_export_public.py`), the procedures' commands against the tools (`tools\test_procedures.py`, skipped without the vault), the ATS match (`tools\test_ats_match.py`) and the docs' facts (`tools\test_doc_facts.py`). The counts in this sentence and across the docs are kept up to date by `python tools\doc_facts.py` (`--check` reports any out of date). The tests set `SETTINGS_FILE=none`, so they check the code against the files whatever is set on the board.

## Checks built into the tools

| Tool | Checks, every time |
| --- | --- |
| `tools\build_pack.py` | CV exactly two pages; the named entry starts page two; letter one page; no em dashes; none of the barred phrases. Exits non-zero and lists the problems on failure |
| `tools\pack_diff.py` | Reports a pack with no `baseline.json` instead of guessing |
| `tools\weekly.py` | Counts only from its two inputs, so a summary can be reproduced |
| `tools\validate.py` | `demoboard`: the demo writes only to the demo board, and only from a folder made by `npm run demo`. Run by the morning run before anything is written; exits non-zero and lists every problem. Against the real 14 October run it correctly flags scores made under rubric v1 against the v2 settings |
